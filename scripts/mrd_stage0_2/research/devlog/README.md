# Devlog: the dated development trace for mrd_stage0_2

Each file under `devlog/<YYYY>/` records one unit of progress: the date, who asked, the question, why it matters, the estimand and null, the code and commit, the experiment-relative artifacts, the numbers, the claim gate and the next steps.

- The devlog is the **only** place where headline numbers live. THEME.md, hypotheses.md, analyses.csv notes and the workstream READMEs cite IDs instead.
- Verdicts (`verdicts:`) and reviewer-alternative states (`alts:`) are declared only in entry front matter. The latest declaration (by date, then id) wins; tools/research_index.py renders the history in STATUS.md and CLAIMS.md.
- devlog/INDEX.md is generated by `python tools/research_index.py write`. Never edit it by hand.

## 1. What counts as a unit of progress

Write one new entry for each of:

- an analysis that creates or updates an artifact slug;
- a long run handed to the user (type run, status partial), and its completion (a second entry that cites the first in `supersedes`);
- a decision;
- a meeting, PI or teammate question set (type meeting; the verbatim questions go in research/asks/ and the entry cites their A-IDs);
- a fix or refactor that changes results or provenance;
- a new app or tool (type tool);
- a docs or context change.

A pure Q&A answer with no code, artifacts or decisions needs no entry.

## 2. Rules

1. **Append-only.** After the day it was written, only `status`, `commit` and typos may change in an entry. Never edit the Results of an old entry.
2. **Corrections go through `supersedes`.** A correction is a new entry that lists the corrected entry in `supersedes: [...]`. Evidence bullets from superseded entries stop counting as current evidence.
3. **Never invent a quote.** The Question section quotes the asker verbatim (in a `>` blockquote) only when the text was recorded. Otherwise write `(reconstructed from <source>)` followed by a paraphrase, and say that the asker is not recorded if that is the case.
4. **Artifacts are relative to the experiment dir** (analysis/..., stage1_dr/..., stage1_dr_variants/..., stage2_supervised/..., preprocessing/..., logs/...). Never write an absolute path, a home-relative path or a path starting with `experiments/` (lint E07, E08). Code paths are repo-relative.
5. **Numbers live only in Results.** Every Results bullet that carries evidence for a hypothesis is tagged `- [H-ID supports|qualifies|contradicts] ...` and should contain at least one number (warning W02).
6. **Claim gate language** follows THEME §6 and AGENTS.md R6: descriptive unless a supported_publication verdict says otherwise; Stage 1 is transductive; LOPO is label transfer, not inductive deployment; P02/P03/P04 are the highest-prevalence patients; an all-zero L1 probe scores constant-score no-skill AP = π.
7. **Regularization provenance.** Every analysis or run entry records `compute`, `c_policy` and `training_n_changed` (lint E10). When training n changes, C must be retuned (AGENTS.md R5); a new entry with `training_n_changed: true` and `c_policy: global_selected` is an error, a backfilled one is warning W11.
8. **Long jobs** are handed to the user: `compute: screen-cpu|screen-gpu`, status partial, and the literal `screen -S <W#>_<topic>` line plus the full command in Implementation.
9. **No unfilled scaffold markers.** `new-entry` copies _TEMPLATE.md with placeholder markers; an entry that still contains one fails lint E15.
10. **Commit field.** Leave `commit: pending` in a new entry; the user (or the next entry) fills in the short hash after the commit. `pending` older than 14 days is warning W01.

Scaffold a new entry with:

```bash
python tools/research_index.py new-entry <slug> --workstream W# [--type analysis] [--analyses D16 ...] [--asks A-...]
```

then fill all 8 sections, and finish with `python tools/research_index.py write && python tools/research_index.py check`.

## 4. Asks file format (research/asks/)

Questions from the user, the PI, a named teammate or a meeting are first appended verbatim to a dated asks file, `research/asks/<YYYY-MM-DD>_<source>.md`. Devlog entries cite the A-IDs in `asks:`; STATUS.md lists the asks that are still unanswered.

Front matter (flat, same subset as devlog front matter):

```text
date: YYYY-MM-DD
source: pi | meeting | teammate | user | report | chat
asked_by: <asked_by vocabulary, see §5>
capture: verbatim | verbatim_from_report | paraphrase | reconstructed
original_location: <text only, no absolute paths>
```

Body: a `# <title>` line, then one line per question:

```text
- [A-YYYYMMDD-NN] (optional asker override, e.g. teammate:Ankit) "<text>" -> <route tokens>
```

Route tokens are comma-separated: W#, W#.n, analysis IDs (D/F/D1DD/V2), H-IDs or THEME.

Ask state is derived, never typed:

- **answered**: a `status: done` entry of type analysis, decision, docs or tool cites the ask, and every routed W#.n task is done;
- **partial**: any non-meeting entry cites it, or any routed task is not open;
- **open**: otherwise.

Entries of type meeting only record asks; they never answer them.

## 5. Vocabularies

| Field | Allowed values | Notes |
|---|---|---|
| `type` | analysis, run, decision, meeting, fix, refactor, tool, docs | analysis and run also need compute, c_policy, training_n_changed |
| `asked_by` | user, PI, meeting:YYYY-MM-DD, meeting:unknown, teammate:<Name>, agent, not_recorded | use not_recorded unless the asker is evidenced in a file, log or transcript |
| `implemented_by` | human, claude-code, codex, cursor-agent, copilot, gemini-cli, aider, other, unknown | the tool or person that wrote the code or document; unknown when not recorded |
| `questions` | Q1, Q2, Q3, QI, meta | Q1 shared vs patient-specific; Q2 strength of evidence; Q3 what DR adds over direct genes; QI interpretability lens (= PI-Q3); meta = process and context |
| `claim_level` | descriptive, inferential, publication, none | publication requires a supported_publication verdict in the same entry (lint E13) |
| `status` | done, partial, blocked, abandoned, superseded | |
| `compute` | none, agent-cpu, notebook-cpu, screen-cpu, screen-gpu | screen-* needs a literal `screen -S` line in Implementation |
| `c_policy` | global_selected, per_fold_tuned, nested, fixed_plus_l2, not_applicable | the Stage 2 C policy of the numbers reported |
| verdict values | supported_descriptive, supported_publication, open, not_supported, retired, grant_gap | declared as `H-ID=verdict` |
| alt states | open, partial, addressed | declared as `H-ID:ALT-ID=state`; the default is open |
| evidence roles | supports, qualifies, contradicts | `- [H-ID role] ...` inside Results only |
| `date_source` | authored, header, git, mtime, log, reconstructed | required when `backfilled: true` |

`date_source` meanings: **authored** = the entry was written on the day of the work; **header** = a date line or a dated title/filename inside the artifact or document; **git** = commit date; **mtime** = file modification time (UTC); **log** = a dated log filename or log timestamp; **reconstructed** = inferred from surrounding evidence. Add a trailing `# comment` naming the evidence.

## 6. Backfill conventions

The 36 entries dated 2026-05-15 to 2026-10-02 (and the 2026-10-08 team-report entry, which is written live) were reconstructed on 2026-10-08 from the repository, git history, experiment logs, file times and the 2026-10-08 fact-check of the team report.

- `backfilled: true` and a `date_source` with a comment naming the evidence (lint E09).
- `date` is the date of the work, not of the backfill. When outputs were regenerated later, the entry keeps the original date and says so in Implementation.
- `commit` is the short hash of the first commit containing the cited code: `git log --follow --diff-filter=A --format=%h -- <path>` (the oldest hit). Code moved by the 2026-07-02 reorganization (db694a3) keeps its original commit (for example 4ada734 for the runners, 91c296b for plans, dbde125 for notebooks). Everything written after 2026-07-23 was first committed in b60a6ee (2026-10-08). The comment says `retro`.
- `run_head` and `dirty_run` record git HEAD when the computation ran:
  - runs before 2026-07-02: `run_head: b381cd5` (the hash the experiment config records) and `dirty_run: true`, because the producing code was uncommitted;
  - runs from 2026-07-24 until b60a6ee: `run_head: 43f19be` and `dirty_run: true`.
  Evidence with `dirty_run: true` cannot back a supported_publication verdict (lint E13); W0.10 re-runs it from a clean tree.
- `implemented_by: unknown` unless the implementer is recorded; `asked_by` is PI, a meeting date or user only where a file, log or transcript shows it, otherwise `not_recorded`.
- Questions are quoted only where the text exists in the repo or the asks files; otherwise they are marked `(reconstructed from ...)`.
- Numbers come only from experiment artifacts and the 2026-10-08 fact-checks of them. Scratch computations that are not repo artifacts are labelled as scratch.
- Backfilled entries record history: D10 and D15 changed training n under one global C (`training_n_changed: true`, `c_policy: global_selected`), which is warning W11 rather than an error.
- Initial verdicts for all 24 hypotheses are declared once, in 2026-10-08_research-spine-adopted, following the migration table. Backfilled entries carry evidence bullets; only the D14 entry also declares a verdict.
- Files outside the repo (the frozen Cursor canvases, agent transcripts, the outer umbrella repo) are named in prose, never by absolute path. The outer repo's repository audit is at `reports/mrd_stage0_2_repository_audit/` relative to the umbrella repo.

## Question
> "TOP PRIORITY: data-driven statistical test for whether to aggregate patients." Step 1: learn factors on all patients and project each patient's cells. Step 2: check per-patient factor distributions. Step 3: if distributions overlap significantly, patients share variation; if distinct, treat them as separate subtypes.

Source: the user's TODO list as recorded in research/asks/2026-10-08_team-report.md (A-20261008-07..10). The original prompt of about 2026-10-01 was not saved, so this text is reconstructed from the report. Stated motivation: P02/P03/P04 seemed to dominate. These are the highest-prevalence patients.

## Why it matters
Q1 needs a data-driven reason to pool patients on one Stage 1 basis before any claim about shared vs patient-specific structure (H-S1-04). The result decides whether the W2 bases (inductive, leave-out, patient-balanced) are a robustness check or a necessity.

## Estimand / null
- **Estimand**, per representation: the variance-weighted mean over factors of the median pairwise 32-bin histogram overlap of factor scores between patients.
  - Computed within CN.label.
  - Normal strata: patients with >=200 cells. Malignant strata: patients with >=20 cells. This is a stratum parameter, not the support rule.
  - Bins are shared over the 1st-99th percentile; tails go into the end bins.
- **Null:** patient labels permuted within label, keeping per-patient counts and fixed bin edges; n_perm = 25.
- **Decision rule** (overlap_decision_rule.json):
  - aggregate_shared when normal weighted overlap >=0.75, normal minimum patient-vs-rest >=0.60, malignant weighted >=0.45 and malignant gap <0.15;
  - separate_subtype_candidate when normal minimum <0.40, or malignant weighted <0.35 with gap >=0.15;
  - otherwise shared_with_location_shift.
- **Single-factor flag:** malignant eta2 >=0.75 AND variance share >=0.15.
- **C policy:** not applicable (no Stage 2 fit).
